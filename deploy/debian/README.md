# Разворачивание сервера Gul на Debian

Один скрипт на чистую машину: Murmur за релеем плюс та настройка безопасности,
без которой ставить на машину ни то, ни другое не стоит.

```sh
curl -fsSLO https://raw.githubusercontent.com/LywwKkA-aD/Gul/main/deploy/debian/install.sh
sudo bash install.sh
```

Требуется **Debian 12 или 13**, минимум 1 ГБ памяти (сборка релея), и домен,
A-запись которого уже указывает на эту машину — по нему выписывается
сертификат, и его же клиент требует в заголовке `Host`.

Debian 11 скрипт возьмёт с предупреждением, но брать его не стоит: поддержка
закончилась **31 августа 2026**, и обновлений безопасности для новой машины
не будет с первого дня.

Скрипт можно запускать повторно: каждая фаза проверяет, что она собирается
создать, и пропускает уже сделанное.

## Что он делает

| Фаза | Что происходит |
|---|---|
| Проверка машины | Debian, память, ядра, сеть |
| gum | ставит `charmbracelet/gum` для диалога |
| Пакеты | podman, uidmap, slirp4netns, firewalld, fail2ban, chrony, unattended-upgrades |
| Администратор | создаёт учётку, принимает **публичный** ключ |
| SSH | свой порт, вход только по ключу — **с защитой от самозапирания** |
| fail2ban | джейл на sshd, на выбранном порту |
| Обновления | автоматические обновления безопасности, синхронизация часов |
| Ядро | rp_filter, syncookies, буферы UDP под QUIC, BBR |
| Юниты | обычные systemd-юниты с `podman run` (не quadlet — см. ниже) |
| Служебная учётка | непривилегированный `murmur`, subuid, lingering |
| Имя сервера | домен и почта для Let's Encrypt, сверка A-записи |
| Сборка релея | клонирует репозиторий и собирает образ **в контейнере** |
| Секреты | три пароля, все в хранилище podman |
| Фаервол | 443→8443 (TCP и UDP), 80→8080, остальное закрыто |
| Запуск и проверка | поднимает, ждёт сертификат, проверяет восемь пунктов |

## Почему не quadlet

Quadlet — правильная форма для такого, но он появился в **podman 4.4**, а
Debian 12 везёт 4.3.1 без генератора вовсе (проверено, а не предположено).
Debian 11 — 3.0.1, архивный репозиторий Kubic — 3.4.2, свежее там взять
неоткуда.

Держать два механизма запуска в одном скрипте ради одного дистрибутива не
стоит того, поэтому скрипт пишет сразу тот systemd-юнит, который quadlet и
сгенерировал бы. Работает от podman 3.0 до 5.x, так что тот же файл заведётся
и на Debian 13, где quadlet уже есть.

Два следствия, которые видны в юнитах:

- **Три тома вместо двух.** Образ пишет сертификат в `/data/acme`, а релею
  надо его читать; podman 4.3 не умеет монтировать подкаталог тома
  (`--mount subpath` появился в 5.0), поэтому сертификат живёт в собственном
  томе, смонтированном ровно по этому пути.
- **`port_handler=slirp4netns`.** Обработчик по умолчанию переписывает адрес
  каждого клиента в 127.0.0.1 — это ослепило бы ограничение по адресам в релее
  и обессмыслило журнал. Этот отдаёт настоящий адрес ценой части пропускной
  способности.

## Про самозапирание

Единственное место, где скрипт останавливается и ждёт человека. Порядок такой:
сначала открывается новый порт и принимается ключ, **пароль при этом ещё
работает**; затем скрипт просит открыть второй терминал и войти по ключу; и
только после подтверждения выключает пароль и закрывает старый порт.

Если вход не получился — ответьте «нет». Скрипт оставит пароль включённым.
Это лучше, чем запертая машина в другой стране.

## Три секрета, и это разные вещи

| Секрет | Что это |
|---|---|
| `MUMBLE_CONFIG_SERVER_PASSWORD` | что человек вводит в клиенте |
| `GUL_RELAY_BEARER` | выводится из него; что проверяет релей на входе |
| `MUMBLE_SUPERUSER_PASSWORD` | админ Murmur, к первым двум отношения не имеет |

Учётка релея выводится бинарём самого релея внутри одноразового контейнера,
читающего пароль из смонтированного секрета. Ни одно из значений не попадает
в командную строку, в файл на хосте или в переменные скрипта.

Пароли сервера и SuperUser показываются **один раз**. Записывайте сразу.

## Сколько людей выдержит канал

Считано по константам протокола, а не на глаз: голос — один пакет Opus на
каждые 10 мс, то есть 100 пакетов в секунду при открытом гейте; каждый пакет
Mumble становится ровно одной ячейкой 256 байт; на проводе с заголовками это
около 330 байт.

| | в одну сторону |
|---|---|
| человек говорит | **264 кбит/с** |
| человек молчит (chaff) | **48 кбит/с** |

Узкое место — исходящий трафик: Mumble не микширует на сервере, каждый
слушатель получает поток каждого говорящего отдельно.

**исходящий = (людей) × (говорят одновременно) × 264 кбит/с**

| одновременно говорят | 50 Мбит/с | с запасом 30% |
|---|---|---|
| один | 189 | 130 |
| двое | 94 | 65 |
| трое | 63 | 44 |

Прикидка: **1 Мбит/с ≈ 4 человека** при одном говорящем, **≈ 2** при двух.
Десять человек по три часа в день — около **160 ГБ в месяц**.

Две вещи, которые стоит знать при росте:

- **Маскировка стоит примерно вшестеро.** Чистый Opus с накладными — около
  50 кбит/с на поток, мы платим 264, потому что каждый голосовой пакет
  добивается до полной ячейки. Это цена прикрытия, и при масштабировании она
  станет главной статьёй.
- **Считать надо пакеты, а не байты.** Сотня слушателей при двух говорящих —
  это 20 000 исходящих пакетов в секунду. Для ядра это заметнее мегабит; двух
  ядер хватает, одного — впритык.

И помните, что до полосы вас ограничит конфиг: `MUMBLE_CONFIG_USERS` по
умолчанию 32, скрипт спрашивает это значение.

## Что проверено, а что нет

Скрипт **полностью прогнан на живой машине** (Debian 12, 2 ядра, 2 ГБ): сборка
релея, секреты, юниты, выпуск сертификата Let's Encrypt, запуск Murmur и релея,
прикрытие снаружи. Найдено и исправлено по результатам прогонов:

- **Образ Murmur нужен с суффиксом `-acme`.** Обычный только *ждёт*
  `/data/acme/mumble.crt` и никогда его не создаёт, поэтому сервер на нём
  висит вечно на сертификате, которого никто не выписывает. Вариант `-acme`
  запускается через supervisord и поднимает менеджер сертификатов рядом с
  Murmur. Сверено по дайджесту с работающим продом.
- `runuser` сохраняет рабочий каталог вызывающего — podman падал с
  `cannot chdir to /root`.
- `collect-licenses.sh` не работает на голом клоне (обходит всю релизную
  матрицу, которой нужен собранный фронтенд).
- Учётка администратора заводилась с заблокированным паролем и не могла
  пользоваться `sudo` вообще.

Раньше, на контейнерных прогонах:
группа `wheel` в Debian не существует (нужна `sudo`), обрыв на `sshd -T`
из-за `pipefail`, и `run()`, которая возвращала успех при любом провале,
отчего все проверки `|| die` были мёртвым кодом.

Отдельно проверено в контейнерах, а не по памяти: версии podman в Debian
11/12/13, отсутствие генератора quadlet, отсутствие `--mount subpath` в 4.3.1,
наличие `podman secret` уже в 3.0.1, работа плоского apt-репозитория Charm,
и то, что образ Murmur сам выпускает сертификат через встроенный
`acme_manage_cert`, а не ждёт его извне.

**Фазы с podman, quadlet, сертификатом и запуском на живой машине не
прогонялись.** Первый запуск делайте на машине, которую не жалко переставить,
и держите под рукой `/var/log/gul-install.log` — туда пишется всё.

## Если что-то пошло не так

```sh
tail -50 /var/log/gul-install.log
journalctl --user -u gul-murmur -u gul-relay   # от пользователя murmur
sudo -u murmur XDG_RUNTIME_DIR=/run/user/$(id -u murmur) systemctl --user status gul-relay
```

Состояние фаз — в `/var/lib/gul-install/*.done`. Удалите нужный файл, чтобы
фаза выполнилась заново.
