# Gul Electron preview

Отдельный клиент на TypeScript, React, Chromium и LiveKit JS. Xray входит
в установщик: пользователю не требуется устанавливать прокси. Транспорт
использует профиль `livekit+vless://…` существующего сервера Gul.

Архитектура и этапы: [ELECTRON-MIGRATION.md](../docs/ELECTRON-MIGRATION.md).
Новый клиент находится в `desktop/`; старый Go/Wails клиент пока сохраняется
для завершения миграции. Серверные broker, LiveKit и Xray остаются отдельными
компонентами.

## Локальный запуск

Нужны Node.js 24, npm и Python 3. Для транспортных тестов нужен `openssl`
в PATH. На Windows Git Bash включает его; Python должен быть доступен как
`python`. На macOS и Linux используется `python3`.

```sh
cd desktop
npm ci
npm run vendor:xray
npm run dev
```

`vendor:xray` скачивает официальный закреплённый Xray 26.3.27 и проверяет
SHA-256 архива. Бинарные файлы не входят в Git. `npm run pack` создаёт
распакованное приложение; `npm run dist -- --publish never` — установщик
текущей ОС. Windows: NSIS/ZIP; Linux: DEB; macOS: DMG. Подпись и нотариализация
релизов требуют отдельной настройки.

## Проверки

```sh
npm run check
npm run format:check
npm run test:coverage
npm audit --audit-level=moderate
```

Порог unit-покрытия исполняемых модулей — 80% строк, ветвей и функций.
Проверяемые модули: полномочия сессии, профили, TLS/SOCKS/TURN, токены,
сигнализация и жизненный цикл медиа. Покрытие unit-тестов не включает React
интерфейс и адаптеры Electron; они проверяются запуском приложения.

Для полного локального E2E подготовьте изолированный стенд инструкцией
`deploy/livekit/stand_reality.py --help`. Его приватные файлы должны оставаться
в игнорируемом `bin/`. Затем:

```sh
GUL_ELECTRON_STAND_DIR=/absolute/path/to/stand npm run test:integration -- e2e/desktop.live.spec.ts
```

Два настоящих Electron-клиента передают синтетические голос, движущееся видео
720p/30 и разные тоны в левом и правом канале. Проверяются декодированные кадры,
PCM, разделение стереоканалов, TURN/TCP, mute/deafen и 20 циклов запуска,
остановки и смены канала. Громкость и локальное отключение проверяются на
выходе WebAudio после GainNode, а не только по состоянию кнопок. После
перезапуска сохраняются адрес и ник, поле пароля остаётся пустым.
Подмена источников существует только в E2E-тесте;
рабочее приложение использует Chromium capture API.

Для проверки упакованного приложения задайте `GUL_PACKAGED_APP_PATH` и
запустите `npm run test:integration -- e2e/packaged.spec.ts`. GitHub workflow
`Electron preview` готовит Windows/Linux артефакты без публикации релиза.

## Что доступно сейчас

Сохранены исходные цвета и шрифты Gul: тёмная боковая панель, светлый чат и
синий акцент. Каналы и участники расположены слева, чат и просмотр — в центре,
список участников — справа. Микрофон, deafen, демонстрация и настройки находятся
в нижней панели; отключение от сервера — рядом со статусом подключения.

Работают голос, каналы, чат, mute/deafen, выбор устройств, RTT, громкость
участников 0–200%, локальное отключение участника, отдельная громкость
демонстрации, полноэкранный просмотр и прекращение просмотра. Настройки
устройств и клавиш сохраняются; история чата хранится по каналам только в
оперативной памяти текущей сессии. Пароль и broker bearer остаются в основном процессе;
интерфейс получает только краткоживущие медиаразрешения. Секреты не сохраняются
в пользовательских настройках.

Просмотр не требует разрешения на захват экрана. При потере связи, выходе
или смене канала захват прекращается. Глобальная клавиша микрофона явно
включается в настройках; сочетание по умолчанию — F8, его можно изменить.
Она работает как переключатель передачи голоса: глобальный key-up Electron
не предоставляет. Режим удержания PTT требует отдельного адаптера ОС.

Захват системного звука пока подключён только на Windows и требует явного
согласия в выборе источника. Он может включать звук Gul; наушники не исключают
его из loopback. Отдельный звук игры без голосов Gul на Windows 10, PipeWire
для Ubuntu и настоящий тест Windows 10 ↔ Ubuntu 26 — следующий этап.
Синтетический E2E подтверждает медиатранспорт, а не захват конкретной игры.

Не проверены часовая нагрузка, аппаратное кодирование на целевых компьютерах
и фактическая нагрузка относительно alpha.6. Из старого клиента ещё требуется
перенести VAD и индикаторы входного уровня, звуковые уведомления, список
сохранённых серверов с безопасным хранилищем паролей и экспорт диагностики.
Автообновление и tray также относятся к следующему этапу. Текущий VPS не изменён.
