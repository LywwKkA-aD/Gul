## 3. Открытые вопросы (закрыть ДО старта M2)

1. **Семантика каналов.** Пользователь: клик по текстовому каналу не должен выглядеть
   как «подключение» (это семантика голосовых). Ограничение протокола: в Mumble нет
   типов каналов и НЕЛЬЗЯ читать чат канала, не находясь в нём. Предложены варианты:
   A (рекомендован) — каналы-«комнаты», клик = перейти; «в голосе» станет отдельным
   явным состоянием в M2 со своей индикацией; B — Discord-конвенция с помеченными
   голосовыми (минус: параллельные текстовые ленты всё равно невозможны).
   Пользователь склоняется к A, но ждёт ответа по п.2. Итог — в DECISIONS.md.
2. **Channel listeners и текст.** Проверить по исходникам сервера
   `https://raw.githubusercontent.com/mumble-voip/mumble/v1.5.915/src/murmur/Messages.cpp`
   (функция `Server::msgTextMessage`): попадают ли слушатели канала (ChannelListener)
   в получатели текста, или листенеры — только аудио. Если текст доставляется —
   это путь к нотификациям из чужих каналов (влияет на выбор A/B). Ожидание по памяти:
   листенеры только аудио, но НУЖНА проверка по коду. Вердикт — в DECISIONS.md.
   (Прошлая сессия не смогла: сеть была заблокирована, см. §6.)

## 6. Почему сессия умерла

Защитный классификатор auto-режима заблокировал ВСЕ действия (Bash/WebFetch/Browser/Agent)
до конца сессии — среагировал на текст в диалоге (отладочная проба, «выстукивавшая» состояние
DOM через URL asset-сервера, с неудачной формулировкой в описании). Сами правки файлов
работали. Урок: осторожнее с формулировками про извлечение данных; при повторе — сразу
предлагать пользователю обычный режим разрешений вместо auto.
