# Разбор дизайн-прототипа (Gul-Prototype-offline.html)

## Резюме

Бандл распакован: manifest содержит 31 ассет (React 18.3.1 UMD, 26 шрифтовых файлов, 2 SVG-спрайта Phosphor), а сам прототип лежит в script type="__bundler/template" как JSON-строка. После декодирования получен читаемый исходник на 10 509 строк — scratchpad/prototype_source.html. Дизайн-система целиком описана одним блоком :root на ~100 строк с комментарием «Единственный источник правды по цвету, ритму и времени»; жёстких hex вне токенов только девять — восемь тинтов аватаров и опции акцента. Ключевое расхождение с PLAN.md: схема не тёмная, а светлая (белое полотно #FFFFFF + серый хром #EEF0F4) с тёмно-синим сайдбаром #1B2440, а иконки — Phosphor-вебфонт, а не lucide-react. Props темы (accent / density / glow) не прокидываются в React-дерево, а через applyTweaks() записываются в document.documentElement как --accent, --row-pad-y/--item-h и --glow-spread, поэтому вся производная палитра пересчитывается через color-mix(in oklab, ...) от одной переменной.

## Находки

### [MAJOR] Схема светлая с тёмным сайдбаром, а не тёмная — прямое расхождение с PLAN.md §6

Комментарий в блоке токенов: «Светлая схема: тёмно-синий сайдбар + белое полотно, синий акцент, тонкое начертание. Две шкалы поверхностей: --bg-* (светлые: полотно, панели, поля) и --sb-* (сайдбар)». Полотно чата --bg-2: #FFFFFF, хром окна --bg-0: #EEF0F4, body { background: var(--bg-0) }. Указанный в задаче #1B2440 — это НЕ фон приложения, а --sb-1, фон левой колонки (и заодно фон сплэш-экрана распаковщика в head бандла). PLAN.md §6 требует «тёмная тема по умолчанию» — прототип этому не соответствует. Нужно решение продукта: либо PLAN.md §6 правится под прототип, либо в Tailwind сразу закладывается вторая (тёмная) схема поверх тех же имён токенов.

Источники: <../../Gul-Prototype-offline.html> · <scratchpad/prototype_source.html (строки 9519–9620, блок :root)> · <../../PLAN.md (§6, строка ~196)>

### [MAJOR] Martian Mono: в бандле есть cyrillic-подсеты, но апстрим считает кириллицу незавершённой

В бандле для Martian Mono ровно 4 @font-face, все weight 500: latin, latin-ext, cyrillic, cyrillic-ext — то есть Google Fonts кириллицу отдаёт, и «ГУЛ»/«НАСТРОЙКИ» рисуются именно ей. При этом README первоисточника (evilmartians/mono) в разделе roadmap помечает «Cyrillic script for Bulgarian, Serbian, and Macedonian» как work in progress. Практический риск: неполное покрытие/неотревьюенные глифы для русского. Поскольку --font-display используется всего в 5 местах и всегда с fallback на IBM Plex Mono, риск локальный, но перед релизом стоит визуально сверить строки «ГУЛ», «НАСТРОЙКИ», «ПОДВАЛ». Лицензия Martian Mono — OFL-1.1, IBM Plex — OFL-1.1, обе пригодны для вендоринга в десктоп-приложение (что для офлайнового Wails-клиента обязательно: CDN-загрузки шрифтов быть не должно).

Источники: <https://github.com/evilmartians/mono> · <scratchpad/prototype_source.html (строки 233–261)>

### [MAJOR] Props темы accent/density/glow: контракт и точные значения

data-props в бандле объявляет три свойства, все в секции «Тема»: accent (editor: color, default #2F52DE, options [#2F52DE, #1F6FB2, #3E4FA8, #5B4BD6]); density (editor: enum, default «Средняя», options [«Компакт», «Средняя», «Воздух»]); glow (editor: enum, default «Тонкое», options [«Нет», «Тонкое», «Заметное»]). Метод applyTweaks() пишет их напрямую в document.documentElement, а не в React-дерево: accent → --accent; density → --row-pad-y (Компакт 2px / Средняя 4px / Воздух 8px) и --item-h (26px / 30px / 34px); glow → --glow-spread (Нет 0px / Тонкое 10px / Заметное 20px). Важно: значение --glow-spread в :root равно 10px, а «Заметное» ставит 20px, тогда как комментарий в токенах говорит «0 / 10px / 18px» — комментарий рассинхронизирован с кодом на 2px. --glow-spread участвует в трёх местах: свечение аватара говорящего (box-shadow ... 0 0 var(--glow-spread) -1px var(--speak-halo)), иконка-логотип на Connect и ореол вокруг говорящего.

Источники: <scratchpad/prototype_source.html (строки 10116 data-props, 10238–10248 applyTweaks, 9562–9564, 10270–10276)>

### [MAJOR] Иконки — Phosphor-вебфонт, а не lucide-react из PLAN.md §2

В бандле два @font-face: "Phosphor" (regular) и "Phosphor-Fill", вместе с полными CSS-таблицами классов (строки 263–9518, ~9,2 тыс. строк — основной вес прототипа). Разметка использует классы вида <i class="ph ph-microphone"> и <i class="ph-fill ph-waveform">. Полный список из 27 иконок: waveform, microphone, microphone-slash, speaker-high, speaker-slash, headphones, hash, users, gear-six, keyboard, sliders-horizontal, info, x, copy, paperclip, paper-plane-right, caret-down, circle-notch, arrow-clockwise, arrow-bend-up-left, warning, warning-circle, prohibit. Fill-начертание применяется строго как индикатор активного/включённого состояния (ph-fill ph-microphone-slash при мьюте, ph-fill ph-speaker-slash при deafen, ph-fill ph-waveform у логотипа, ph-fill ph-paper-plane-right у кнопки отправки) — это семантическое правило, его надо сохранить. PLAN.md §2 фиксирует lucide-react; расхождение надо разрешить явно. Официальный React-пакет Phosphor — @phosphor-icons/react (MIT), поддерживает 6 начертаний и props size/weight/color, tree-shaking; вебфонт-вариант — @phosphor-icons/web (MIT).

### [minor] Совместимость CSS с WebView Wails: color-mix и text-wrap:pretty

Вся производная палитра держится на color-mix() — по MDN это Baseline «Widely available» с мая 2023, oklab поддерживается как пространство интерполяции (и является дефолтным). На Windows (WebView2, Chromium) и macOS (WKWebView) это безопасно. Риск — Linux: Wails использует WebKitGTK, и версия из репозитория дистрибутива может быть старее. Отдельно text-wrap:pretty на теле сообщения — Baseline 2024 «Newly available» (октябрь 2024), то есть заметно свежее; это чисто косметическое улучшение и деградирует безопасно. Рекомендация: color-mix оставить (запасной вариант — сгенерировать статические hex для 4 вариантов акцента на этапе сборки), text-wrap:pretty оставить как progressive enhancement, проверить рендер на минимальной поддерживаемой версии WebKitGTK в CI-матрице (PLAN.md §9 уже включает ubuntu-latest).

Источники: <https://developer.mozilla.org/en-US/docs/Web/CSS/color_value/color-mix> · <https://developer.mozilla.org/en-US/docs/Web/CSS/text-wrap-style> · <../../PLAN.md (§9)>

### [info] Акцент и все его производные вычисляются через color-mix(in oklab) от одной переменной

Базовый --accent: #2F52DE. Производные: --accent-hover = color-mix(in oklab, var(--accent), black 10%); --accent-active = ... black 22%; --accent-weak = color-mix(in oklab, var(--accent) 10%, var(--bg-1)); --accent-line = color-mix(in oklab, var(--accent) 45%, var(--line)); --accent-text = color-mix(in oklab, var(--accent), black 8%); --on-accent: #FFFFFF (текст и иконки на акценте и на цветных аватарах). Цвет речи («свеча»): --speak = color-mix(in oklab, var(--accent), white 14%), --speak-halo = color-mix(in oklab, var(--speak) 42%, transparent). Активный канал в сайдбаре: --sb-active = color-mix(in oklab, var(--accent) 46%, var(--sb-1)). Мьют-иконки на тёмном: --sb-danger = color-mix(in oklab, var(--danger), white 26%). В комментарии зафиксировано намерение: «переопределения --accent достаточно, чтобы поехала вся тема». Варианты акцента из data-props: #2F52DE (дефолт), #1F6FB2, #3E4FA8, #5B4BD6.

### [info] Тени, z-шкала, тайминги и easing

Тени построены как «кромка + мягкая синеватая подложка»: --sh-sm = 0 0 0 1px var(--line); --sh-md = 0 0 0 1px var(--line), 0 6px 16px rgba(20,27,49,.10); --sh-lg = 0 0 0 1px var(--line), 0 22px 48px rgba(20,27,49,.22). Обрати внимание: границы почти везде сделаны через box-shadow-ring, а не border — это сознательный приём (поля ввода не «прыгают» при фокусе). Z-шкала именованная, «без 9999»: --z-base 0, --z-dropdown 100, --z-tooltip 200, --z-modal 300. Тайминги: --t-fast 90ms (hover, tint, иконки), --t-mid 160ms (поповеры, тумблеры, баннер), --t-slow 260ms (модал, смена экрана), --t-pulse 1800ms (пульс речи). Easing: --e-out cubic-bezier(.2,.8,.3,1), --e-in-out cubic-bezier(.4,0,.2,1). Кейфреймы: gul-halo (ореол речи), gul-bar (три полоски эквалайзера, 620ms, задержки 0/120/240ms), gul-spin, gul-level (анимация метра уровня, 2600ms), gul-in (появление тултипа/меню/баннера), gul-modal. Есть блок @media (prefers-reduced-motion: reduce), сводящий все длительности к 1ms.

Источники: <scratchpad/prototype_source.html (строки 9593–9618, 9639–9648)>

## Рекомендации

- Перенести блок :root из прототипа в frontend/src/styles/tokens.css ДОСЛОВНО, включая комментарии, и объявить его единственным источником правды (как и написано в его шапке). Не переписывать значения в JS-объект и не дублировать в tailwind.config — иначе теряется главное свойство системы: переопределил --accent, поехала вся тема. Файл импортировать первым в frontend/src/index.css.
- В Tailwind v4 подключать токены через @theme inline, а не переопределять значения: `@import "tailwindcss"; @import "./tokens.css"; @theme inline { --color-bg-0: var(--bg-0); ... --color-accent: var(--accent); --color-speak: var(--speak); --font-display: var(--font-display); --font-ui: var(--font-ui); --font-mono: var(--font-mono); --radius-sm: var(--r-sm); --radius-md: var(--r-md); --radius-lg: var(--r-lg); --shadow-sm: var(--sh-sm); --shadow-md: var(--sh-md); --shadow-lg: var(--sh-lg); --ease-out: var(--e-out); --ease-in-out: var(--e-in-out); }`. Именно `inline` обязателен: без него Tailwind резолвит переменную в точке объявления и рантайм-переопределение --accent из applyTweaks перестанет работать. Источник: https://tailwindcss.com/docs/theme (раздел «Referencing other variables»).
- Не пытаться загонять в @theme производные на color-mix (--accent-hover, --accent-weak, --sb-active, --speak-halo, --danger-weak, --warning-weak) как отдельные цвета Tailwind — они и так доступны как обычные CSS-переменные. Использовать их через произвольные значения: bg-[var(--accent-hover)], shadow-[0_0_0_1px_var(--accent-line)]. Это дешевле, чем плодить 15 утилит-классов, и сохраняет реактивность.
- Шкалу отступов не переопределять: --s-1..--s-6 кратны 4px, что совпадает с дефолтным --spacing Tailwind (0.25rem), поэтому p-1..p-6 уже дают 4/8/12/16/20/24px «из коробки». Отдельно объявить только то, чего нет: --spacing-item (var(--item-h)) и --spacing-row (var(--row-pad-y)) — либо просто писать h-[var(--item-h)] / py-[var(--row-pad-y)], чтобы плотность оставалась управляемой из настроек.
- Кейфреймы (gul-halo, gul-bar, gul-spin, gul-level, gul-in, gul-modal) объявить в @theme через --animate-*: `@theme { --animate-halo: gul-halo 1800ms var(--e-out) infinite; @keyframes gul-halo { ... } }` — тогда доступны как animate-halo. Блок @media (prefers-reduced-motion: reduce) перенести в базовый слой без изменений.
