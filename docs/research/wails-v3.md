# Верификация: Wails v3

## Резюме

На 21.08.2026 актуальная beta — v3.0.0-beta.11 (опубликована 20.08.2026); беты выходят практически ежедневно как автоматические nightly-релизы с master, стабильным остаётся v2.14.0. Два пункта исходного плана противоречат реальности: Wails v3 требует Go 1.25+ (в v3/go.mod директива `go 1.25.0`), а не 1.23, и шаблона `react-ts` не существует — TypeScript занял «голое» имя, то есть нужен `wails3 init -t react` (шаблон при этом отдаёт React 18, а не 19, и без Tailwind). Упаковка полностью готова: NSIS и MSIX на Windows, .app/.dmg/universal на macOS, AppImage/deb/rpm/AUR на Linux. Linux-базой стал GTK4 + WebKitGTK 6.0, а GTK3 + WebKit2GTK 4.1 остаётся только через `-tags gtk3` и будет удалён в v3.1. Глобальные хоткеи (`app.GlobalShortcut`) и системный трей (`app.SystemTray`) — штатные нативные API без сторонних зависимостей, но на Wayland финальную комбинацию клавиш выбирает композитор через XDG-портал. Внутри серии бет (beta.0 → beta.11) ломающих изменений публичного API нет; единственный разрыв — beta.8 убрала пайплайн бинарных релизов, теперь CLI ставится только через `go install`.

## Находки

### [CRITICAL] Требуется Go 1.25+, а не Go 1.23 — план проекта нужно исправить

В v3/go.mod на теге v3.0.0-beta.11 стоит директива `go 1.25.0`. Начиная с Go 1.21 такая директива является жёстким минимумом: тулчейн младше 1.25.0 откажется собирать модуль. Официальная страница статуса подтверждает: "All targets require Go 1.25 or later for development". Мобильные гайды (iOS и Android) также требуют "Go 1.25+ and npm". ВНИМАНИЕ на несогласованность документации: страница установки (docs/src/content/docs/getting-started/installation.mdx) до сих пор содержит вкладку "Go (At least 1.24)" — это устаревший текст, который противоречит и go.mod, и странице статуса. Первоисточником следует считать go.mod. В любом случае заявленный в плане Go 1.23+ недостаточен.

### [MAJOR] Wayland: гарантировать конкретную комбинацию глобального хоткея невозможно — решает композитор

Файл v3/pkg/application/global_shortcut_linux.go выбирает бэкенд по типу сессии: `isWaylandSession()` читает XDG_SESSION_TYPE (авторитетно, если задан), иначе смотрит наличие WAYLAND_DISPLAY. На X11 используется XGrabKey-бэкенд (newX11GlobalShortcuts), на Wayland — портальный (newPortalGlobalShortcuts).

Комментарий в исходнике формулирует ограничение прямо: "On Wayland sessions there is, by design, no way for a client to grab keys directly. The only sanctioned mechanism is the XDG Desktop Portal's org.freedesktop.portal.GlobalShortcuts interface, so the portal backend is used there. Note that under the portal the compositor (and ultimately the user) decides the final key binding". Практический вывод: на Wayland запрошенная комбинация — это лишь пожелание, реальная привязка может отличаться, и пользователю может быть показан системный диалог. Кроме того, `Register` возвращает ошибку, если приложение уже запущено и ОС отвергла регистрацию (обычно комбинацию занял кто-то другой); если регистрация была отложенной (до `app.Run`), отказ ОС приходит не возвратом из Register, а в обработчик ошибок приложения.

### [info] Глобальные хоткеи и системный трей — штатные API на самом App, без сторонних зависимостей

В v3/pkg/application/application.go структура App содержит поля `SystemTray *SystemTrayManager` и `GlobalShortcut *GlobalShortcutManager` (инициализируются в конструкторе через newSystemTrayManager/newGlobalShortcutManager).

GlobalShortcutManager (global_shortcut_manager.go) публично предоставляет: `Register(accelerator string, callback func()) error`, `Unregister(accelerator string) error`, `UnregisterAll() error`, `IsRegistered(accelerator string) bool`, `GetAll() []string`. Из документации: "Global shortcuts are built directly on each platform's native facilities and add no third party dependencies". Регистрировать можно до `app.Run` — привязка к ОС откладывается до старта приложения. Конфликты обрабатываются по семантике "error and preserve": повторная регистрация того же акселератора возвращает ошибку, исходная привязка сохраняется. Колбэк выполняется в отдельной горутине; для работы с UI из колбэка документация рекомендует `application.InvokeSync`. Формат акселераторов совпадает с меню: "CmdOrCtrl+Shift+G", "Ctrl+Alt+K", "Super+D", "Ctrl+Shift+F5". Реализации есть для darwin, windows, linux (x11 и portal) плюс global_shortcut_unsupported.go. Важно не путать с `app.KeyBinding` — тот срабатывает только когда окно приложения в фокусе.

SystemTray (systemtray.go) даёт: `SetLabel`, `Label`, `SetIcon`, `SetDarkModeIcon`, `SetMenu`, `SetIconPosition`, `Run`, `Show`/`Hide`, `ShowMenu`, `ShowWindow`/`HideWindow`, `ToggleWindow`, `PositionWindow(window, offset)`, а также applySmartDefaults (по умолчанию правый клик открывает меню). Платформенные файлы: systemtray_darwin.go/.m/.h, systemtray_linux.go, systemtray_windows.go, а также systemtray_android.go и systemtray_ios.go. В beta.2 задокументированы "system tray smart defaults and popup auto-hide behaviour" с регрессионными тестами (#5840).

### [info] Мобильная поддержка (iOS и Android) — экспериментальная и не блокирует desktop-бету

Страница статуса: "Android and iOS support is experimental and does not block the desktop Beta". Контракт беты ("The v3 Beta contract covers desktop applications") распространяется только на Windows amd64/arm64 (нужен WebView2 Runtime), macOS Intel/Apple Silicon и Linux amd64/arm64. Гайды guides/mobile/ios.mdx и android.mdx оба помечены бейджем `Experimental` с предупреждением "iOS/Android support is experimental and may change in future releases".

Технически поддержка реальная: один и тот же main.go и фронтенд. iOS — WKWebView + UIKit-хост, ассеты отдаются через кастомную схему `wails://` без открытых портов, требуется macOS с полноценным Xcode (командных line tools недостаточно), iOS-специфика настраивается через `application.Options.IOS`. Android — системный WebView + WebViewAssetLoader, Go компилируется в разделяемую библиотеку `libwails.so` (GOOS=android + NDK), загружаемую небольшим Java-хостом; требуются Android SDK с platform-tools, SDK platform API 35, build-tools и NDK 26.3.x, JDK (например OpenJDK 21) и ANDROID_HOME/ANDROID_SDK_ROOT; собирать можно на macOS, Linux и Windows. Обе платформы требуют Go 1.25+ и npm. В CLI есть соответствующая обвязка (ios_xcode_gen.go, android_overlay_gen.go, шаблон `ios`), есть пример v3/examples/mobile (Kitchen Sink). В beta.4 задачи сборки Android переведены на arm64 по умолчанию, в beta.8 починен Xcode-проект iOS (-ObjC и наследуемые linker flags).

## Рекомендации

- Пинить v3.0.0-beta.11 точным тегом и в go.mod (`github.com/wailsapp/wails/v3 v3.0.0-beta.11`), и в команде установки CLI (`go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.11`). Категорически не использовать @latest: беты выходят практически ежедневно как автоматические nightly-сборки с master, и @latest сделает сборки невоспроизводимыми. Зафиксировать версию CLI в README/Makefile/CI одной переменной, чтобы обновлять её в одном месте.
- Немедленно исправить план по Go: минимум Go 1.25, а не 1.23. Обновить директиву `go` в go.mod проекта, образы CI и локальные требования. С Go 1.23/1.24 модуль просто не соберётся из-за `go 1.25.0` в v3/go.mod.
- В скриптах инициализации использовать `wails3 init -t react` (это и есть TypeScript-вариант). Имени `react-ts` не существует и оно приведёт к ошибке валидации; `react-js` — это JavaScript-вариант. Перед автоматизацией проверить актуальный список через `wails3 init -l`.
- Заложить в план ручной апгрейд фронтенда после `wails3 init`: шаблон приносит React ^18.2.0 с @types/react ^18.x, поэтому React 19 нужно ставить отдельно вместе с обновлением типов. Vite (^8.0.5) и @vitejs/plugin-react (^6.0.0) уже свежие — их трогать не нужно. Tailwind не входит ни в один встроенный шаблон, его придётся добавлять самостоятельно; после установки обязательно прогнать `npm run build` (в шаблоне это `tsc && vite build --mode production`), чтобы поймать несовместимость типов React 19 на раннем этапе.
- Строить Linux-ветку на GTK4 + WebKitGTK 6.0 — это дефолт. Базовый дистрибутив для CI и docker-образов брать не ниже Ubuntu 24.04 (официально заявленная база), пакеты: `libgtk-4-dev` и `libwebkitgtk-6.0-dev` для apt, `gtk4-devel` и `webkitgtk6.0-devel` для dnf. Флаг `-tags gtk3` рассматривать только как временный запасной путь для старых дистрибутивов и заранее считать его тупиковым: он поддерживается лишь до конца v3.0.x и удаляется в v3.1.
- Как можно раньше протестировать глобальные хоткеи на Wayland, а не только на X11 и macOS. На Wayland финальную комбинацию назначает композитор через XDG Desktop Portal, поэтому UI не должен обещать пользователю конкретное сочетание клавиш — показывайте фактически назначенное, предусмотрите путь отказа (портал недоступен, комбинацию занял другой процесс) и подписку на ошибки приложения для отложенных регистраций, сделанных до `app.Run`.
- Встроить `wails3 doctor` (или `wails3 doctor-ng -n` для неинтерактивного режима в CI) в онбординг разработчика и в пайплайн — он показывает установку Go, недостающие системные библиотеки и готовые команды установки для конкретного пакетного менеджера. Дополнительно `wails3 tool capabilities` даёт быстрый ответ, доступен ли GTK4 или только GTK3.
- Мобильную поддержку (iOS/Android) считать вне области проекта на этой стадии: она официально экспериментальная и выведена за рамки контракта совместимости беты, то есть может измениться без предупреждения. Если мобильный таргет всё же нужен позже — заранее закладывать macOS с полноценным Xcode для iOS и Android SDK API 35 + NDK 26.3.x + JDK 21 для Android.
- Не завязывать установку CLI на загрузку готовых бинарников из GitHub Releases: начиная с beta.8 пайплайн бинарных релизов удалён, v3 распространяется только тегами, а CLI ставится через `go install`. Если такой шаг уже есть в скриптах — переписать на go install.
- Настроить отслеживание изменений: смотреть релизы wailsapp/wails с фильтром на v3.0.0-beta.*, ленту CHANGELOG и в первую очередь искать пометки BREAKING. Внутри серии бет ломающих изменений API пока не было, поэтому обновление по бетам относительно безопасно — но обновляться стоит осознанным шагом с прогоном сборки на всех трёх платформах, а не автоматически.
- Перед финальным решением по версии перепроверить, не вышла ли более свежая бета: на момент проверки (21.08.2026) последней была beta.11 от 20.08.2026, и при ежедневном ритме релизов номер сдвигается быстро. При этом обновляться до самой свежей ночной сборки в момент старта проекта не обязательно — разумнее взять бету, которая уже несколько дней провисела без регрессов.
- При спорных вопросах сверяться с исходниками, а не с текстом документации: на сайте v3.wails.io есть устаревшие места (например, требование Go 1.24 на странице установки и упоминание команды `wails doctor` из v2). Первоисточники — v3/go.mod, код в v3/pkg/application, Taskfile-шаблоны в v3/internal/commands/build_assets и страница docs/src/content/docs/status.mdx на нужном теге.
