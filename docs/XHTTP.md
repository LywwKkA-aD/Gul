# XHTTP: оценка перехода

Проверено 8 октября 2026 года. Рабочий транспорт Gul остаётся
VLESS / TCP / REALITY. XHTTP проверен отдельно на локальном стенде;
на действующем VPS конфигурация не менялась.

## Что меняется

XHTTP — транспорт Xray, который можно сочетать с REALITY или TLS.
Официальный проект описывает HTTP/2, HTTP/3, потоковую и пакетную отправку,
разделение направлений и работу через CDN. Есть
[пример VLESS + XHTTP + REALITY](https://github.com/XTLS/Xray-examples/tree/main/VLESS-XHTTP-Reality/minimal-steal_others)
и [описание режимов разработчиком](https://github.com/XTLS/Xray-core/discussions/4113).

Из этого следует: смена TCP на XHTTP при прямом подключении к тому же VPS
не скрывает его IP от провайдера. Для подключения через CDN нужен отдельный
вариант с доменом и TLS. Его доступность зависит от конкретного CDN,
промежуточных сетей и настроек потоковой передачи. Обещать обход блокировки
IP по одному лишь названию транспорта нельзя.

## Что уже проверено

На закреплённом в Gul Xray **26.3.27** отдельный Linux Docker стенд прошёл
проверки TCP/REALITY, XHTTP/REALITY `stream-one` и `packet-up`:

- проверка внутреннего TLS по доверенному сертификату;
- HTTPS-запросы к broker через SOCKS;
- настоящий STUN-запрос к TURN по TCP через тот же путь;
- запрет обращения через туннель к другому порту.

Для каждого режима выполнено 20 новых HTTPS-соединений. Медиана полного
запроса составила 67,5 / 84,1 / 116,1 мс соответственно. Это измерение
локального стенда с эмуляцией Linux amd64 на Apple Silicon, включая запуск
клиента запроса и рукопожатия. Оно не измеряет задержку голоса, пропускную
способность или доступность из России. В этом опыте XHTTP не дал выигрыша
по времени запроса.

Последний найденный официальный релиз —
[Xray 26.9.30](https://github.com/XTLS/Xray-core/releases/tag/v26.9.30).
В отдельной попытке с ним даже контрольный TCP/REALITY не завершил
внутреннее TLS-рукопожатие. Причина пока не установлена; этот опыт нельзя
считать сравнением XHTTP. Обновление ядра требует отдельной проверки,
пины и SHA-256 действующей сборки не изменены.

## Объём реализации в Gul

| Вариант | Работа | Предварительная оценка |
| --- | --- | --- |
| Дополнительный XHTTP + REALITY | Строгие поля `type`, `path`, `mode` в профиле; генерация клиентской и серверной конфигурации; проверка сохранённых адресов; туннель WSS/TURN; переподключения и повторы демонстраций | 1–2 рабочих дня |
| XHTTP + TLS через CDN | Всё перечисленное, отдельные адрес CDN и origin, домен/DNS/сертификат, настройка reverse proxy и CDN, ограничения трафика и таймаутов, тест длительного голоса и стрима | 3–5 рабочих дней плюс проверка у пользователей |

Это инженерная оценка объёма, а не срок или гарантия. Голос, экран и звук
демонстрации остаются в LiveKit; Electron уже содержит Xray. Переписывать
медиа-клиент ради этого не требуется. Фиксированное назначение туннеля,
проверка внутреннего TLS и запрет прямого сетевого fallback сохраняются.

Для проверки оператора нужны отдельный тестовый адрес и длительная сессия
Windows 10 ↔ Ubuntu: голос одновременно с 720p/30 и 1080p/60, потеря сети,
переподключение, повторная демонстрация и простой соединения. Только после
этого можно выбирать новый транспорт по умолчанию. Совместимость CDN
с потоковым режимом нужно проверять на выбранном сервисе отдельно.
