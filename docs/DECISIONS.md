# Решения Gul 0.8

Актуальная архитектура описана в [PLAN.md](../PLAN.md). Этот документ фиксирует
решения действующей Electron версии; старые исследовательские материалы
и клиент доступны в истории Git.

## 2026-10-07 — Один media engine

Клиент полностью переведён на Electron/TypeScript и LiveKit JS. Chromium
владеет голосом, экраном, playback и WebRTC DSP; отдельный Go voice engine
удалён. Это убирает обмен PCM между движками, собственную синхронизацию A/V
и зависимость Linux WebView от доступности WebRTC. Цена — память и размер
поставляемого Chromium; меньшую нагрузку нужно измерять, а не предполагать.

Voice mono48k использует WebRTC AEC/NS/AGC и небольшой AudioWorklet для gain/VAD.
Screen audio остаётся stereo без голосовой обработки. WebAudioMix даёт gain
до 200%; HTML audio при таком playback не звучит параллельно.

## 2026-10-07 — Встроенный официальный Xray

Используется закреплённый Xray v26.3.27 как отдельный bundled executable,
вместо собственной адаптации handshake. Архивы проверяются SHA-256 по manifest;
лицензия и digest включаются в поставку. Пользователь не устанавливает прокси.

Сигнализация и TURN/TCP имеют специальные loopback мосты в main. Настройка
HTTP proxy Electron не считается маршрутизацией WebRTC ICE. Внешний транспорт
REALITY TCP, локальный SOCKS аутентифицирован, mux/UDP выключены, назначения
фиксированы. Неверный ключ, пароль или TLS сертификат завершают подключение.

Voice и screen используют отдельные Rooms/peer connections. TCP потоки
разделены; packet loss всё ещё может задержать поток и конкурировать за канал.
Профиль и общий пароль совместимы с действующим LiveKit REALITY сервером.

## 2026-10-07 — Broker остаётся самостоятельным сервером

Go module `server/` хранит только broker/API. LiveKit SFU, TURN, HAProxy и Xray
на VPS сохраняют свою роль; сервер не перекодирует screen media. JSON поля,
парольный hash, REALITY UUID derivation и role ownership сохранены.
Legacy source/deploy/build удалены из текущего дерева.

## 2026-10-07 — Просмотр независим от захвата

Возможность подписаться на чужой экран не зависит от наличия местного capture
backend или пользовательского разрешения. Только выбранная демонстрация
подписывается для playback; переключение/остановка просмотра освобождает tracks.
Демонстрация автоматически запрашивает изображение и системный звук после
выбора источника; захват требует актуальной channel epoch. Громкость просмотра
регулируется отдельно в диапазоне 0–200%.

## 2026-10-07 — Alpha.1: первоначальная семантика системного звука

720p30 и один видеослой выбраны для начального режима с небольшой нагрузкой.
Системный звук Windows 10/Linux может содержать голоса Gul и не равен
изолированному звуку выбранной игры. Устройству Gul нужен отдельный вывод,
либо incoming audio отключают во время демонстрации. Наушники loopback
не устраняют. Windows 11/macOS own-audio exclusion остаётся capability request.

## 2026-10-07 — Alpha.2: Linux audio без Gul и исправления демонстрации

Предыдущее ограничение Linux заменено отдельным libpulse helper: он копирует
playback потоки других приложений в приватный stereo source. Gul и его дочерние
процессы исключаются по UID/PID/start time и дереву процессов; неизвестные
идентичности исключены. Default sink/source и маршруты потоков не меняются.
Helper запускается main только после разрешённого display capture текущей эпохи,
а renderer открывает ровно сгенерированный audio device. PCM не проходит IPC.
Общий output mix не используется как fallback; остановка убирает приватные устройства.
Windows 10 остаётся с ограничением общего output mix.

Wayland portal уже выдаёт выбор источника: второй диалог не показывается.
В прочих picker пустые названия получают понятные подписи. LiveKit JS 2.22.3
пропускает отсутствующий VP8 fmtp при нормализации BUNDLE. Узкий instance-local
hook исправляет только bitrate hint пустых publisher transceivers; параметры
реальных codecs, remote SDP и media transport не меняются.

## 2026-10-07 — Alpha.3: повторный запуск экрана и состояние значков

Одиночный канал воспроизвёл два пропущенных случая LiveKit 2.22.3: первый
offer содержит SDP mids до их назначения transceivers, а SDK повторно добавляет
bitrate hint при обработке ответа SFU. Hook теперь нормализует только
placeholder VP8 в publisher local offers и SDK-munged remote answers.
Первоначальный ответ сервера, remote offers, реальные codec constraints и
подсказка bitrate 1800 остаются сохранены. Неназначенные mids определяются
только по явно несендящему recvonly/inactive разделу, без сопоставления по позиции.

Остановка демонстрации сохраняет pending до завершения unpublish/disconnect.
Epoch, capture generation и принадлежность Room защищают новую демонстрацию
от запоздавшей очистки прежней. Regression использует управляемую задержку
unpublish, а Electron E2E повторяет включения в одиночном канале и с зрителями.
Просмотр и захват повторно проверяют своё поколение запроса после ожидания
очистки, до создания Room: отменённое действие не оставляет лишнее соединение.

Список участников и нижняя панель используют один SVG с зачёркиванием для
mute/deafen. Login и sidebar показывают существующий appicon.png; asset также
проверяется в packaged приложении. Палитра и компоновка сохранены.

Собственная индикация речи использует существующий AudioWorklet, без ожидания
события активного говорящего с сервера. UI обновляется на границах речи;
20 Hz meter не перерисовывает всё приложение. Dialog scroll находится во
внутреннем контейнере; кнопка закрытия остаётся вне скролла.

## 2026-10-07 — Alpha.4: обработка микрофона и Windows audio

Изменение AEC/NS/AGC через applyConstraints в закреплённом Chromium не меняло
фактический DSP. Теперь настройка перезапускает capture с полным набором флагов,
сохраняет mute/PTT и применяет изменения последовательно. После отмены или
ошибки новый сырой микрофон не публикуется. Очередь настроек UI объединяет
только изменённые поля с актуальным состоянием, включая повторное открытие.

В голосовой AudioWorklet добавлен закреплённый RNNoise WASM 0.2.1 с локальной
моделью. Голосовой контекст фиксирован на 48 kHz, выход mono. Фреймы RNNoise —
480 samples; адаптер Chromium render blocks имеет постоянные ограниченные
буферы. Задержка алгоритма с адаптером — около 30 мс. Готовность процессора
подтверждается до открытия микрофона, поздняя ошибка оставляет выход закрытым.
Демонстрации остаются stereo без шумодава/AGC. Test fixture: открытая речь и
детерминированный шум вентилятора/клавиш, без пользовательских записей.

Windows использует bundled native WASAPI process loopback с
EXCLUDE_PARENT_PROCESS_TREE. Helper определяет реального родителя и проверяет
SID/session/start time; произвольный PID/endpoint не принимается. Поддержка
проверяется Activate/Initialize без чтения аудио, а не по номеру Windows.
Capture запускается после выбора источника и подтверждения текущей эпохи.
При отсутствии API доступно только видео, общий микс не используется.

PCM проходит по одноразовому loopback WebSocket с точными Origin/Host/path,
привязкой к текущему окну/захвату и очередью не более 120 мс. IPC содержит
только разрешение/lease. Heartbeat/parent exit закрывают helper; отмена,
смена канала и позднее завершение закрывают старую запись/Room. Это не меняет
обычный вывод и не отключает голос собеседников.

Windows/X11 picker встроен в Gul: превью экранов/окон, клавиатура и отдельное
подтверждение. Native source IDs остаются в main; renderer получает случайные
одноразовые ключи. Wayland portal сохраняет собственный picker без второго диалога.

## 2026-10-07 — Локальные настройки и безопасность

Адрес/ник сохраняются после успешного входа. Password encryption через
safeStorage разрешена только по явному согласию и защищённому OS backend;
при недоступном keyring пароль не сохраняется. Alpha.2 сохраняет consent
отдельно от cipher, восстанавливает его и показывает статус после запуска;
ошибки encrypt/write/decrypt не скрываются и не заменяют защищённый cipher
открытым паролем. Renderer не получает saved
password/broker bearer; media JWT привязаны к роли, комнате и эпохе.

Диагностический ZIP содержит только разрешённые события/метрики и версии;
сетевые адреса, credentials и чат исключены из структуры. Update check
использует фиксированный GitHub API и открывает проверенную страницу;
автоматического запуска установщика нет.

## Проверка решений

Локально 348 unit tests: macOS 346 passed/2 platform skips; TS coverage
89.66% строк, 90.46% ветвей, 88.70% функций. Gate — минимум 80% каждой метрики. Все четыре packaged CI цели прошли smoke с sandbox,
Linux DEB установлен.
Windows helper прошёл регистрацию/освобождение F8 hook, Linux portal —
семь DBus сценариев. Это не доказательство физического hold PTT.

Два Electron клиента через обновлённый удалённый REALITY сервер прошли
synthetic voice, чат и 20 циклов screen+audio. Самостоятельный broker прошёл
race/vet/build и TLS/TURN/ACL smoke; broker coverage — 92.8% при переносе.

Native Linux capture на DISPLAY/PulseAudio стенде подтвердил движущиеся кадры
в пределах 720p и stereo PCM 440 Гц L / 660 Гц R через TURN/TCP.
В alpha.2 native Electron E2E показал разделение 49 дБ и исключение собственного
Gul 880 Гц на 52 дБ; игра и Gul остаются слышны в обычном выводе.
Сохранённый вход после полного перезапуска прошёл с настоящим GNOME Keyring.
Остаются physical mic, игра Windows 10 ↔ Ubuntu 26, физические
клавиши и часовой soak. Публикация выполняется после успешного релизного workflow.
